# Dashboard + จัดการวัสดุ (เฟส 1a) — Design

สถานะ: รอผู้ใช้อนุมัติ · 22 ต.ค. 2569

## เป้าหมาย

เว็บแอปที่เจ้าหน้าที่ Lab ล็อกอินแล้วเห็น dashboard สรุปวัสดุคงคลังแบบสวยและมืออาชีพ และเพิ่ม / แก้ไข / ลบ วัสดุในชีต `Stock_record` ได้ ใช้ได้ทั้งมือถือและคอมพิวเตอร์

### อยู่ในขอบเขต
- หน้า Login ตรวจกับแท็บ `User`
- Dashboard: การ์ด KPI, กราฟ, รายการใกล้หมดอายุ (≤ 6 เดือน), รายการหมดสต็อก
- หน้ารายการวัสดุ: ค้นหาทันทีขณะพิมพ์ (ชื่อหรือรหัสบางส่วน), กรองสถานะ, เพิ่ม / แก้ไข / ลบ
- คำนวณ Quantity = In − Out และ Amount = Unit Price × Quantity ทุกครั้งที่บันทึก

### นอกขอบเขต (เฟสถัดไป)
- บันทึกรายการเคลื่อนไหว IN / OUT แยกรายครั้ง, ประวัติการใช้
- สแกนบาร์โค้ด / QR, ใบเบิก A4, Safety Stock, Web Notification, รายการสั่งซื้อ, รายงานรายเดือน
- หน้าจัดการผู้ใช้ในแอป (เพิ่มผู้ใช้ทำในชีตไปก่อน)

## สถาปัตยกรรม

**อัปเดต 25 ต.ค. 2569:** เปลี่ยนไปรันบน Google Apps Script (ADR 0002) — ส่วนสถาปัตยกรรมด้านล่างเป็นแบบเดิม

```
app/
  login/page.tsx            ฟอร์มล็อกอิน
  (app)/layout.tsx          sidebar (จอใหญ่) / แถบเมนูล่าง (มือถือ)
  (app)/page.tsx            Dashboard
  (app)/items/page.tsx      ตารางวัสดุ + ค้นหา + ฟอร์มเพิ่ม/แก้ไข + ยืนยันลบ
middleware.ts               กันทุกหน้า ยกเว้น /login
lib/
  sheets/client.ts          สร้าง Sheets client จาก env
  inventory/item.ts         ชนิดข้อมูล Item, แปลงแถว ↔ Item, validate, คำนวณ  (pure)
  inventory/stats.ts        KPI, สถานะ, เรียงลำดับความเร่งด่วน              (pure)
  inventory/thaiDate.ts     แปลง/แสดงวันที่ พ.ศ.                             (pure)
  inventory/repository.ts   list / create / update / remove บนชีต
  auth/users.ts             อ่านแท็บ User, ตรวจรหัสผ่าน
  auth/session.ts           cookie เซสชันเซ็นด้วย JWT (jose), อายุ 8 ชั่วโมง
```

### การเขียนลงชีต
- **เพิ่ม**: แทรกแถวใหม่เหนือแถวรวม แล้วเขียนค่า
- **แก้ไข**: อ่านชีตใหม่ หาแถวจาก Item code แล้วเขียนทับแถวนั้น (ไม่เชื่อเลขแถวจากหน้าเว็บ เพราะคนอื่นอาจแทรกแถวในชีตไปแล้ว)
- **ลบ**: หาแถวจาก Item code แล้วลบทั้งแถว (มีกล่องยืนยันก่อน)
- หลังเขียน อัปเดตแถวรวมมูลค่าให้เป็นผลรวม Amount ใหม่ และ revalidate หน้า
- ชนกันพร้อมกัน: ใครบันทึกหลังชนะ (ผู้ใช้น้อย ยอมรับได้)

### สถานะวัสดุ (ใช้ทั้ง dashboard และตาราง)
1. **หมดอายุแล้ว** — EXP. < วันนี้
2. **ใกล้หมดอายุ** — EXP. ภายใน 6 เดือน
3. **หมดสต็อก** — Quantity = 0
4. **ปกติ**

ตารางเรียงรายการที่ต้องสนใจขึ้นก่อน (ตามลำดับข้างบน แล้วตามวันหมดอายุ / จำนวนคงเหลือน้อยไปมาก) สถานะ "ใกล้หมด" ตามจำนวนขั้นต่ำรอเฟส Safety Stock

### Dashboard
- KPI: วัสดุทั้งหมด, มูลค่าคงคลังรวม, หมดสต็อก, ใกล้หมดอายุ (≤ 6 เดือน), หมดอายุแล้ว
- กราฟ: สัดส่วนสถานะ (โดนัท), มูลค่าคงคลังตามบริษัท (แท่งแนวนอน, 8 อันดับแรก), อัตราการใช้ Out ÷ In สูงสุด
- รายการใกล้หมดอายุ 6 รายการแรก พร้อมจำนวนวันที่เหลือ
- ดีไซน์ตามตัวอย่างที่ทำไว้: ฟอนต์ IBM Plex Sans Thai, พื้นเทาอ่อน การ์ดขาว สีหลักน้ำเงิน สีเตือนส้ม/แดง

## ล็อกอินและความปลอดภัย (ADR 0003)
- ตรวจ username + password กับแท็บ `User`
- รองรับรหัสผ่านทั้งแบบข้อความธรรมดา (ของเดิม) และ bcrypt เมื่อล็อกอินสำเร็จด้วยรหัสแบบข้อความธรรมดา ระบบเขียน bcrypt hash ทับให้อัตโนมัติ รหัสจริงจึงค่อยๆ หายจากชีต
- ล็อกอินผิดแสดงข้อความกลางๆ ไม่บอกว่าผิดที่ username หรือ password
- ไฟล์ชีตต้องเลิกแชร์แบบ "ทุกคนที่มีลิงก์" แชร์ให้เฉพาะ Service Account และเจ้าหน้าที่

## การตั้งค่า (env)
`GOOGLE_SHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY`, `SESSION_SECRET` — มีคู่มือตั้งค่า Service Account และ Vercel ทีละขั้นใน `docs/setup.md`

## การจัดการข้อผิดพลาด
- ฟอร์ม: ตรวจทั้งฝั่งหน้าเว็บและเซิร์ฟเวอร์ (zod) แสดงข้อความภาษาไทยใต้ช่อง
- ชีตเชื่อมไม่ได้ / ไม่มีสิทธิ์: หน้าแสดงข้อความภาษาไทยพร้อมสาเหตุที่น่าจะเป็น
- หาแถวที่จะแก้/ลบไม่เจอ (ถูกลบไปแล้ว): แจ้งผู้ใช้และโหลดข้อมูลใหม่

## การทดสอบ
- Vitest unit test สำหรับโค้ด pure: แปลงแถว ↔ Item (รวมตัวเลขมีจุลภาค เช่น " 4,368.00"), สูตรคำนวณ, validate, วันที่ พ.ศ., สถานะและการเรียงลำดับ, KPI
- repository ทดสอบกับ Sheets client ปลอม (in-memory) ครอบคลุม เพิ่มเหนือแถวรวม / แก้ / ลบ / ออกรหัส LAB ถัดไป / อัปเดตแถวรวม
- ตรวจหน้าเว็บจริงด้วย Playwright กับข้อมูลปลอม (โหมด `SHEETS_FAKE=1`) ก่อนส่ง PR
